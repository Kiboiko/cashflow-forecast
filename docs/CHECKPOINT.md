# Финальный чек-поинт: что и как показывать (15 минут)

Порядок проверки у организаторов: сначала минимальные требования, потом задачи со звёздочкой. Ниже — команды для
контрольного датасета, сценарий демо и таблица «требование → где показать». Команды — PowerShell из папки `backend/`.

## 1. Контрольный датасет: загрузить, посчитать прогноз, метрики и логи (≈3 минуты на 150 компаний)

Положите архив, например, в корень репозитория как `control.zip` (подойдёт и папка с `all_operations.csv`, и одна
выписка CSV; справочник `companies.csv` необязателен).

```powershell
cd backend
uv run python scripts/evaluate.py --data ..\control.zip --publish --prepare-service ..\data\control
```

Если контрольный датасет — **продолжение тех же компаний** (например, октябрь 2026-го и дальше, истории в нём мало),
добавьте историю из датасета разработки: прогнозы будут сделаны на конец истории и сверены с контрольным периодом.
Если факта меньше 30 дней, горизонт проверки автоматически сокращается до того, сколько его есть (не меньше 7 дней).

```powershell
uv run python scripts/evaluate.py --data ..\control.zip --history ..\data\raw --publish --prepare-service ..\data\control
```

Проверено на трёх репетиционных наборах: новые компании без справочника (13 с), продолжение на 45 дней (9 с),
продолжение на 21 день — горизонт 21 день (8 с). На всех 150 компаниях — ≈2,5 минуты.

Что получится в `reports/control/control/`:

| Файл | Что это | Что показать жюри |
|---|---|---|
| `evaluation_log.txt` | пошаговый журнал проверки: загрузка, категоризация, отсечки, прогнозы, метрики, время каждого шага | «пошаговые логи вычисления» |
| `trace_<компания>.txt` | как построен прогноз одной компании: 13 шагов от данных до риска и советов (красная, жёлтая и зелёная компании) | «как вы строите прогноз» |
| `evaluation.md` | Accuracy, Precision, Recall, Specificity, F1, матрицы ошибок, MAE, MSE, RMSE, WAPE, rel-MAE, покрытие P10–P90, ROC-AUC, PR-AUC, Brier, надёжность вероятностей, сравнение с наивными подходами | «метрики» |
| `figures/confusion.png` | матрицы ошибок жёлтого и красного уровня | «матрица ошибок» |
| `figures/backtest_*.png` | прогноз против факта: пойманный разрыв, пропущенный и спокойный случай | графики |
| `figures/forecast_*.png` | прогноз на 30 дней от последней даты: история остатка и коридор P10–P90 | графики |
| `forecast_summary.csv`, `forecast_daily.csv` | прогноз по каждой компании: уровень, шанс, дата и сумма разрыва; остаток по дням | «результат расчёта прогноза» |

`--publish` кладёт метрики на страницу «Как мы считаем» (вверху — пометка «Контрольный датасет…», ниже — матрицы
ошибок и все метрики): файл `reports/backtest_<дата>_<время>_control.json` локальный API подхватывает сразу, Docker —
после `docker compose up --build -d`. Вернуть отчёт датасета разработки — удалить этот файл. Модель заморожена: на
контрольных данных ничего не подбирается, калибровка шанса — из репозитория.

Пошаговый журнал расчёта есть и в интерфейсе: «Главная» → внизу «Как посчитан этот прогноз — шаг за шагом».

Как читать метрики. Каждая точка — компания и конец месяца, в котором модель видит только прошлое. «Разрыв был» —
операционного остатка (без денег владельца) не хватило хотя бы в один из следующих 30 дней. «Тревога» — жёлтый уровень
(шанс ≥10%) или красный (шанс ≥35% или разрыв вероятен в ближайшие 7 дней). MAE и RMSE — ошибка ожидаемого остатка в
рублях; rel-MAE — та же ошибка в долях от обычного остатка компании (сравнимо между малыми и крупными бизнесами).

## 2. Контрольные компании в интерфейсе (скриншоты графиков)

Номера компаний контрольного датасета могут совпасть с уже загруженными, поэтому для него — отдельная база.
Остановите API демо (окно с uvicorn) и запустите его на контрольных данных:

```powershell
cd backend
$env:DATA_DIR = "..\data\control"; $env:DATABASE_URL = "sqlite:///control.db"; $env:JURY_AS_OF = "last"
uv run python scripts/seed_demo.py --jury --as-of 2026-09-30      # дата — конец периода из evaluation_log.txt
uv run uvicorn app.main:create_app --factory --port 8000
```

Откройте http://localhost:5173 → блок «Для жюри» → выберите компанию → «Открыть» (первый вход — до минуты).
Прогноз строится от последней даты выписки — той же, что в отчёте. Показать: «Главная» (график остатка с коридором,
светофор, причины, обязательные платежи, рекомендации), «Платежи», «Что если», «Как мы считаем» (метрики контрольного
датасета).

Вернуться к демо-персонам: остановить API и запустить снова без переменных окружения
(`Remove-Item Env:DATA_DIR, Env:DATABASE_URL, Env:JURY_AS_OF`, потом `uv run uvicorn app.main:create_app --factory --port 8000`).

## 4. Требования кейса → где показать

| Требование | Где в продукте | Чем подтверждено |
|---|---|---|
| **Мин. 1.** Прототип принимает историю операций и выдаёт прогноз | «Операции» → загрузка выписки (CSV датасета, 1С); режим жюри; `scripts/evaluate.py` | тесты `tests/api`, контрольный датасет |
| **Мин. 2.** Модуль категоризации | «Операции»: категория у каждой операции, исправление с запоминанием (только категории своего направления) | 99,9% операций распознано; ML-добивка — 94% на незнакомых компаниях (`reports/categorization_ml.md`) |
| **Мин. 3.** Модель прогноза с проверкой качества | «Как мы считаем»; `reports/backtest.md` | бэктест без утечек, 765 точек: rel-MAE 0,19 против 0,25 у наивного, ROC-AUC 0,94, матрица ошибок |
| **Мин. 4.** График остатка и список предупреждений | «Главная»: график P10/P50/P90, светофор, карточка предупреждений; колокольчик в шапке | скриншоты |
| **Задача 1.** Разбор и категоризация | см. Мин. 2 | |
| **Задача 2.** Регулярные платежи, счета и налоги из внешних источников | «Платежи»: регулярные (зарплата с переносом выходных, аренда, кредиты), ЕНП 28-го с авансами УСН, счета из учётной системы, CSV, 1С | у каждого события виден источник |
| **Задача 3.** Остаток по дням минимум на 30 дней | «Главная», горизонт 30/60/90 в «Настройках» | |
